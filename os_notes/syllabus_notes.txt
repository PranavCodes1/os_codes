UNIT 1: Introduction to Operating Systems
1.1 Operating System Definition
Definition: An Operating System (OS) is system software that acts as an interface between the user and computer hardware. It manages computer resources and provides services to programs.

Functions of Operating System:
1. Process Management – Manages running processes.
2. Memory Management – Allocates and deallocates memory.
3. File Management – Creates, deletes and manages files.
4. Device Management – Controls input and output devices.
5. Security – Protects the system from unauthorized access.
6. Resource Management – Allocates CPU, memory and other resources.
7. User Interface – Provides an interface for users.
Examples: Windows, Linux, macOS, Android and iOS.


1.2 Computer System Architecture
Computer system architecture describes how processors are organized in a computer system.

There are three main types:
1. Single Processor System
1. Contains only one main CPU.
2. Executes one instruction at a time.
3. CPU handles all processing activities.
4. Simple and less expensive.
5. Example: Traditional personal computers.
2. Multiprocessor System
1. Contains two or more processors.
2. Processors share memory and other resources.
3. Performs multiple tasks simultaneously.
4. Increases system performance.
5. Improves reliability.
6. Also called a parallel system.

Advantages:
- Increased processing speed.
- Better resource utilization.
- Improved reliability.
- Supports multitasking.

3. Clustered System
1. Consists of two or more independent computers connected together.
2. Computers work together as a single system.
3. Each computer is called a node.
4. They share resources through a network.
5. Used for high availability and high performance.

Advantages:
- High reliability.
- Better performance.
- Load sharing.
- Provides backup if one system fails.


1.3 Operating System Structure
Operating System structure describes how different components of an OS are organized.
1. Simple Structure
1. OS has no well-defined structure.
2. Components are not divided into separate layers.
3. All components can interact with each other.
4. Difficult to maintain and debug.
5. Example: MS-DOS.
2. Layered Structure
1. OS is divided into multiple layers.
2. Each layer performs a specific function.
3. Upper layers use services of lower layers.
4. Makes debugging and maintenance easier.
5. Provides better organization.

Advantages:
- Easy to design.
- Easy to debug.
- Better modularity.

Disadvantages:
- Slower due to communication between layers.
- Difficult to define proper layers.
3. Microkernel Structure
1. Keeps only essential functions inside the kernel.
2. Other services run in user space.
3. Provides communication through message passing.
4. Improves security and reliability.
5. Example: MINIX 3.

Advantages:
- More secure.
- Easy to extend.
- Easy to maintain.

Disadvantages:
- Communication overhead.
- May reduce performance.
4. Modules Structure
1. OS is divided into separate modules.
2. Each module performs a specific function.
3. Modules can be loaded and unloaded dynamically.
4. Modules communicate through defined interfaces.
5. Example: Linux.

Advantages:
- Flexible.
- Easy to maintain.
- Better organization.
5. Hybrid Structure
1. Combines features of different OS structures.
2. Uses monolithic kernel and microkernel concepts.
3. Provides better performance and flexibility.
4. Used in modern operating systems.
5. Examples: Windows and macOS.


1.4 Computing Environments
A computing environment describes how computers and resources are used to perform tasks.

1. Traditional Computing
1. Uses desktop computers and workstations.
2. Computing resources are available locally.
3. Users interact directly with the computer.
4. Example: Desktop computer in an office.

2. Mobile Computing
1. Uses portable devices.
2. Provides computing services while moving.
3. Uses wireless networks.
4. Examples: Smartphones and tablets.

3. Distributed Computing
1. Multiple computers work together.
2. Computers are connected through a network.
3. Tasks are divided among different computers.
4. Improves resource sharing and performance.

4. Client-Server Computing
1. Consists of clients and servers.
2. Client requests services.
3. Server processes requests and provides responses.
4. Server manages shared resources.
5. Example: Web browser requesting a webpage from a web server.

5. Peer-to-Peer (P2P) Computing
1. All computers are called peers.
2. Each computer can act as both client and server.
3. Resources are shared directly between computers.
4. No central server is required.
5. Example: BitTorrent.

Difference between Client-Server and Peer-to-Peer:
| Client-Server | Peer-to-Peer |
|---|---|
| Central server is present. | No central server is required. |
| Server provides services. | Peers share resources. |
| Client requests services. | Each peer can request and provide services. |
| Centralized management. | Decentralized management. |

1.5 Operating System Services
Operating System provides services to users and programs.

Important OS Services:
1. User Interface – Provides GUI or CLI.
2. Program Execution – Loads and executes programs.
3. I/O Operations – Performs input and output operations.
4. File System Management – Creates, deletes and manages files.
5. Communication – Allows processes to communicate.
6. Error Detection – Detects hardware and software errors.
7. Resource Allocation – Allocates CPU, memory and devices.
8. Accounting – Tracks resource usage.
9. Protection and Security – Prevents unauthorized access.


1.6 User and Operating System Interface
An interface allows users to communicate with the operating system.

Types of Interfaces:
1. Command Line Interface (CLI)
1. Users interact using text commands.
2. Commands are entered through a keyboard.
3. Requires knowledge of commands.
4. Fast and powerful for experienced users.
5. Example: Linux Terminal.

2. Graphical User Interface (GUI)
1. Uses graphical elements.
2. Includes icons, windows, menus and buttons.
3. Easy to use.
4. Does not require memorizing commands.
5. Example: Windows Desktop.


3. Touch Screen Interface
1. Users interact through touch.
2. Supports tapping, swiping and gestures.
3. Commonly used in mobile devices.
4. Example: Android smartphones.


1.7 Booting
Definition: Booting is the process of starting a computer and loading the operating system into main memory.

Steps of Booting:
1. Power ON – Computer receives electrical power.
2. BIOS/UEFI – Firmware starts executing.
3. POST – Checks hardware components.
4. Bootloader – Finds and loads the operating system kernel.
5. Kernel Loading – OS kernel is loaded into RAM.
6. System Initialization – Device drivers and system services are started.
7. Login Screen – System becomes ready for users.

Types of Booting:
1. Cold Booting – Starting a computer from a completely powered-off state.
2. Warm Booting – Restarting a computer without completely switching off the power.


1.8 System Calls
Definition: System calls are the interface between user programs and the operating system kernel. They allow programs to request services from the OS.

Types of System Calls:
1. Process Control – Create and terminate processes.
   - Examples: fork(), exit(), wait().
2. File Management – Create, open, read and write files.
   - Examples: open(), read(), write(), close().
3. Device Management – Request and release devices.
4. Information Maintenance – Get system information.
   - Examples: getpid(), time().
5. Communication – Exchange data between processes.
   - Examples: pipe(), shared memory operations.
6. Protection – Control access permissions and security.
   - Example: chmod().

Advantages:
- Provides access to OS services.
- Provides controlled hardware access.
- Improves security.
- Simplifies application development.

1.9 System Programs
Definition: System programs are software that provide a convenient environment for developing and executing programs.

Types of System Programs:
1. File Management – Create, delete and copy files.
2. Status Information – Display system information.
3. File Modification – Edit and modify files.
4. Programming Language Support – Compilers and interpreters.
5. Program Loading and Execution – Load and execute programs.
6. Communication – Support communication between users and systems.
7. Background Services – Perform background operations.
Examples: File Explorer, Command Prompt, Linux Terminal, compilers and text editors.



UNIT 2: Processes and Threads

2.1 Process Concept
What is a Process?
Definition: A process is a program that is currently in execution.

Characteristics of a Process:
1. Has its own process ID (PID).
2. Contains program code.
3. Has its own memory space.
4. Uses CPU time and other resources.
5. Has a process state.

Difference between Program and Process:
| Program | Process |
|---|---|
| Program is a passive entity. | Process is an active entity. |
| Stored on disk. | Loaded into memory. |
| Contains instructions. | Executes instructions. |
| Does not have a process state. | Has a process state. |

Process States
A process passes through different states during execution.

Five Main Process States:
1. New – Process is being created.
2. Ready – Process is waiting for CPU.
3. Running – Process is currently executing.
4. Waiting – Process is waiting for an event or I/O operation.
5. Terminated – Process has completed execution.

Process Control Block (PCB)
Definition: PCB is a data structure maintained by the operating system to store information about a process.

Information stored in PCB:
1. Process ID – Unique identification number.
2. Process State – Current state of process.
3. Program Counter – Address of next instruction.
4. CPU Registers – Stores register values.
5. CPU Scheduling Information – Priority and scheduling details.
6. Memory Management Information – Memory allocation details.
7. Accounting Information – CPU usage and time limits.
8. I/O Status Information – Allocated devices and open files.

Importance: PCB helps the OS manage processes and perform context switching


2.2 Process Scheduling
Definition: Process scheduling is the activity of selecting a process from the ready queue and allocating the CPU to it.
Scheduling Queues
1. Job Queue – Contains all processes in the system.
2. Ready Queue – Contains processes waiting for CPU.
3. Device Queue – Contains processes waiting for I/O devices.

Types of Schedulers
1. Long-Term Scheduler (Job Scheduler)
- Selects processes from the job pool.
- Loads selected processes into memory.
- Controls the degree of multiprogramming.
- Executes less frequently.
2. Short-Term Scheduler (CPU Scheduler)
- Selects a process from the ready queue.
- Allocates CPU to the selected process.
- Executes very frequently.
- Must be fast.
3. Medium-Term Scheduler
- Temporarily removes processes from memory.
- Later brings them back into memory.
- Performs swapping.
- Helps manage memory.

Context Switch
Definition: Context switching is the process of saving the state of the current process and loading the state of another process.

Steps:
1. Stop the currently running process.
2. Save its CPU state in PCB.
3. Select another process.
4. Load its saved state from PCB.
5. Start execution of the new process.

Disadvantage: Context switching creates overhead because CPU time is spent switching instead of executing processes.


2.3 Operations on Processes
1. Process Creation
1. A process creates another process.
2. Creating process is called Parent Process.
3. New process is called Child Process.
4. Each process gets a unique PID.
5. Parent and child may execute simultaneously.
Example: In UNIX/Linux, fork() is used to create a new process.

2. Process Termination
1. A process terminates after completing execution.
2. OS releases its allocated resources.
3. Exit status is returned to the parent.
4. A process can also be terminated by another process.
Reasons for Termination:
- Normal completion.
- Error during execution.
- Memory or resource limit exceeded.
- Terminated by parent process.


3. Synchronization of Parent and Child Processes
1. Parent and child processes may execute simultaneously.
2. Parent may wait for the child to complete.
3. wait() system call is used in UNIX/Linux.
4. Parent collects the child's termination status.
5. Synchronization prevents certain execution-related problems.


2.4 Threads
Thread Overview
Definition: A thread is the smallest unit of CPU execution within a process.
1. A process can contain one or more threads.
2. Threads share code, data and files of the same process.
3. Each thread has its own stack and registers.
4. Threads execute independently.
5. Threads are also called lightweight processes.

Benefits of Threads
1. Responsiveness – Application remains responsive.
2. Resource Sharing – Threads share process resources.
3. Economy – Thread creation is less expensive.
4. Scalability – Uses multiple CPU cores effectively.
5. Better Performance – Supports concurrent execution.


Multithreading Models
Multithreading models describe the relationship between user threads and kernel threads.

1. Many-to-One Model
1. Many user threads are mapped to one kernel thread.
2. Thread management is done in user space.
3. If one thread blocks, all threads may block.
4. Cannot achieve true parallelism.


2. One-to-One Model
1. Each user thread is mapped to one kernel thread.
2. Supports parallel execution.
3. If one thread blocks, others can continue.
4. Creating many threads increases overhead.


3. Many-to-Many Model
1. Many user threads are mapped to multiple kernel threads.
2. Allows multiple threads to execute simultaneously.
3. Provides better flexibility.
4. Reduces overhead compared to one-to-one in some implementations.


UNIT 3: CPU Scheduling

3.1 Basic Concepts

3.1.1 CPU-I/O Burst Cycle
Definition: A process execution consists of alternating CPU burst and I/O burst activities.
1. CPU Burst – Time during which a process uses the CPU.
2. I/O Burst – Time during which a process performs or waits for I/O operations.
3. A process alternates between CPU and I/O bursts.
4. Process terminates after its final CPU burst.
Example:
CPU Burst → I/O Burst → CPU Burst → I/O Burst → CPU Burst

3.1.2 CPU Scheduler
Definition: CPU scheduler selects one process from the ready queue and allocates the CPU to it.

Functions:
1. Selects the next process.
2. Allocates CPU to the selected process.
3. Improves CPU utilization.
4. Helps in efficient process execution.

3.1.3 Preemptive Scheduling
Definition: Preemptive scheduling allows the operating system to take the CPU away from a running process and allocate it to another process.

Advantages:
1. Better response time.
2. Suitable for interactive systems.
3. High-priority processes get CPU quickly.
Disadvantages:
1. More context switching.
2. Increased overhead.
3. More complex implementation.
Example: Round Robin, SRTF and Preemptive Priority Scheduling.

Non-Preemptive Scheduling: Once a process gets the CPU, it continues until it terminates or enters the waiting state.

Examples: FCFS and Non-Preemptive SJF.
3.1.4 Dispatcher
Definition: Dispatcher is the OS component that gives control of the CPU to the process selected by the short-term scheduler.

Functions:
1. Performs context switching.
2. Switches to user mode.
3. Starts execution of the selected process.
Dispatch Latency: Time taken by the dispatcher to stop one process and start another process.

3.1.5 Scheduling Criteria
These criteria are used to evaluate CPU scheduling algorithms.
1. CPU Utilization – Percentage of time CPU remains busy. (Higher is better.)
2. Throughput – Number of processes completed per unit time. (Higher is better.)
3. Turnaround Time – Total time taken to complete a process. (Lower is better.)
4. Waiting Time – Total time spent waiting in the ready queue. (Lower is better.)
5. Response Time – Time between submitting a request and getting the first response. (Lower is better.)

Important Formulas:
- Turnaround Time (TAT) = Completion Time − Arrival Time
- Waiting Time (WT) = Turnaround Time − Burst Time
- Response Time (RT) = First CPU Start Time − Arrival Time
- Average Waiting Time = Total Waiting Time / Number of Processes
- Average Turnaround Time = Total Turnaround Time / Number of Processes

3.2 CPU Scheduling Algorithms
3.2.1 First Come First Serve (FCFS)
Definition: FCFS is a non-preemptive scheduling algorithm in which the process that arrives first gets the CPU first.

Working:
1. Processes are arranged according to arrival time.
2. First arriving process gets the CPU.
3. It executes until completion or blocking.
4. Next process gets the CPU.

Advantages:
- Simple to implement.
- Easy to understand.
- No starvation.

Disadvantages:
- High average waiting time.
- Convoy effect may occur.
- Not suitable for interactive systems.

Convoy Effect: When short processes wait for a long process to complete.

3.2.2 Shortest Job First (SJF)
Definition: SJF is a scheduling algorithm that selects the process with the smallest CPU burst time.

Types:
1. Non-Preemptive SJF – Once a process starts execution, it continues until completion or blocking.
2. Preemptive SJF (Shortest Remaining Time First) – A new process with a shorter remaining burst time can preempt the running process.

Advantages:
- Gives minimum average waiting time when burst times are known.
- Efficient for short processes.

Disadvantages:
- Difficult to predict CPU burst time.
- Long processes may suffer starvation.
- Not suitable when burst times are unknown.

3.2.3 Priority Scheduling
Definition: Priority scheduling selects the process having the highest priority for CPU execution.
1. Each process is assigned a priority.
2. Highest-priority process executes first.
3. Can be preemptive or non-preemptive.
4. If priorities are equal, FCFS can be used.

Advantages:
- Important processes execute first.
- Useful in priority-based systems.

Disadvantages:
- Low-priority processes may suffer starvation.
- Priority management is required.

Aging: Aging is a technique of gradually increasing the priority of waiting processes to prevent starvation.


3.2.4 Round Robin Scheduling (RR)
Definition: Round Robin is a preemptive scheduling algorithm in which each process gets a fixed amount of CPU time called Time Quantum.

Working:
1. Processes are placed in a circular ready queue.
2. Each process gets CPU for a fixed time quantum.
3. If completed, it leaves the queue.
4. If not completed, it goes to the end of the queue.
5. The next process gets the CPU.

Advantages:
- Fair CPU allocation.
- Good response time.
- Suitable for time-sharing systems.
- Prevents starvation in normal operation.

Disadvantages:
- Too small time quantum causes more context switches.
- Too large time quantum behaves like FCFS.
- Performance depends on time quantum.

3.2.5 Multilevel Queue Scheduling
Definition: Multilevel Queue Scheduling divides the ready queue into multiple separate queues based on process types.

Working:
1. Ready queue is divided into different queues.
2. Each queue has its own scheduling algorithm.
3. Processes are permanently assigned to a particular queue.
4. CPU is allocated according to queue priority or time sharing.
Example of Queues:
1. System Processes.
2. Interactive Processes.
3. Batch Processes.
4. Student Processes.

Advantages:
- Separates different types of processes.
- Each queue can use a different algorithm.
- Easy to manage process categories.

Disadvantages:
- Lower-priority queues may suffer starvation.
- Processes cannot easily move between queues.


3.2.6 Multilevel Feedback Queue Scheduling
Definition: Multilevel Feedback Queue Scheduling allows processes to move between different queues based on their CPU usage and behaviour.

Working:
1. Multiple queues are created.
2. Each queue has a different priority.
3. New processes enter the highest-priority queue.
4. Processes using too much CPU may move to lower-priority queues.
5. Waiting processes may move to higher-priority queues.

Advantages:
- Flexible scheduling.
- Prevents starvation using priority adjustment.
- Suitable for interactive processes.

Disadvantages:
- Complex to implement.
- Requires proper selection of queue priorities and time quantum.

Important Comparison of CPU Scheduling Algorithms
| Algorithm | Type | Selection Basis |
|---|---|---|
| FCFS | Non-preemptive | Arrival time |
| SJF | Non-preemptive | Shortest burst time |
| SRTF | Preemptive | Shortest remaining time |
| Priority | Both | Highest priority |
| Round Robin | Preemptive | Time quantum |
| Multilevel Queue | Both | Fixed queue priority |
| Multilevel Feedback Queue | Both | Process behaviour and queue priority |





UNIT 4: Memory Management

4.1 Introduction
Definition: Memory management is an operating system function that manages primary memory (RAM) and allocates memory to processes.

Functions:
1. Keeps track of memory usage.
2. Allocates memory to processes.
3. Deallocates memory after execution.
4. Provides memory protection.
5. Manages sharing of memory.
6. Supports virtual memory.
4.1.1 Basic Hardware
1. Main memory (RAM) stores programs and data currently being used.
2. CPU directly accesses registers and main memory.
3. Registers are the fastest storage locations.
4. Memory Management Unit (MMU) translates logical addresses into physical addresses.
5. OS protects memory from unauthorized access.
Memory Hierarchy:
        Registers
           ↓
       Cache Memory
           ↓
       Main Memory
           ↓
      Secondary Storage

Speed decreases as we move down the hierarchy, while storage capacity generally increases.

4.1.2 Address Binding
Definition: Address binding is the process of mapping program instructions and data to memory addresses.

Types of Address Binding:
1. Compile-Time Binding
   - Address is decided during compilation.
   - Used when memory location is known in advance.
2. Load-Time Binding
   - Address is decided when the program is loaded into memory.
   - Requires relocatable code.
3. Execution-Time Binding
   - Address is decided during program execution.
   - Process can move between memory locations.
   - Requires hardware support like MMU.
   
4.1.3 Logical versus Physical Address Space
Logical Address:
1. Generated by the CPU.
2. Also called virtual address.
3. Visible to the program.
4. Translated by MMU.
Physical Address:
1. Actual address in main memory.
2. Used by memory hardware.
3. Obtained after address translation.

Difference:
| Logical Address | Physical Address |
|---|---|
| Generated by CPU. | Actual memory address. |
| Also called virtual address. | Also called real address. |
| Visible to the program. | Not directly visible to the user program. |
| Translated by MMU. | Used by memory hardware. |


4.1.4 Dynamic Loading
Definition: Dynamic loading is a technique in which a routine is loaded into memory only when it is needed.

Features:
1. Entire program is not loaded at once.
2. Required routines are loaded during execution.
3. Saves memory space.
4. Useful for large programs.
5. Improves memory utilization.
Example: A rarely used error-handling routine is loaded only when an error occurs.

4.1.5 Dynamic Linking and Shared Libraries
Dynamic Linking:
1. Linking of library routines is postponed until execution time.
2. Program uses a small piece of code called stub.
3. Stub locates the required library routine.
4. Reduces program size.
5. Allows libraries to be updated separately.
Shared Libraries:
1. Library code can be shared by multiple programs.
2. Avoids loading multiple copies of the same library.
3. Saves memory.
4. Improves resource utilization.
Example: Shared libraries in Linux (.so files).


4.2 Swapping
Definition: Swapping is a memory management technique in which a process is temporarily moved from main memory to secondary storage and later brought back into memory.

Working:
1. OS selects a process from main memory.
2. Process is moved to backing store (swap space).
3. Free memory becomes available.
4. Another process is loaded into memory.
5. The swapped-out process can later be brought back.

Advantages:
- Increases degree of multiprogramming.
- Frees main memory.
- Allows more processes to run.

Disadvantages:
- Slow due to disk operations.
- Increases execution time.
- Excessive swapping reduces performance.

4.3 Contiguous Memory Allocation
Definition: Contiguous memory allocation is a technique in which each process is allocated a single continuous block of memory.
1. Main memory is divided into partitions.
2. Each process occupies one continuous block.
3. OS occupies a separate portion of memory.
4. Remaining memory is allocated to processes.
4.3.1 Memory Mapping and Protection
1. Base Register – Stores the starting physical address of a process.
2. Limit Register – Stores the size of the process's logical address space.
3. CPU generates a logical address.
4. MMU checks whether the address is within the limit.
5. Valid address is added to the base register.
6. Invalid addresses generate a trap to the OS.
Formula:

Physical Address = Base Address + Logical Address


4.3.2 Memory Allocation
There are three important memory allocation techniques.

1. First Fit
- Allocates the first available memory block that is large enough.
- Simple and fast.
- May create external fragmentation.
2. Best Fit
- Allocates the smallest available block that is large enough.
- Searches for the closest size.
- May create many small unused holes.
3. Worst Fit
- Allocates the largest available memory block.
- Leaves a large remaining free block.
- May waste large memory blocks.


4.3.3 Fragmentation
Definition: Fragmentation is the wastage of memory that occurs when memory is divided into small or unusable pieces.

Types:

1. Internal Fragmentation
1. Occurs inside an allocated memory block.
2. Allocated block is larger than required memory.
3. Unused space remains inside the block.
4. Common in fixed-size memory allocation.
2. External Fragmentation
1. Occurs outside allocated memory blocks.
2. Free memory is divided into small non-contiguous blocks.
3. Total free memory may be sufficient, but continuous memory is unavailable.
4. Common in variable-size memory allocation.

Difference:
| Internal Fragmentation | External Fragmentation |
|---|---|
| Occurs inside allocated blocks. | Occurs between allocated blocks. |
| Memory is wasted within a block. | Free memory is divided into holes. |
| Common in fixed-size allocation. | Common in variable-size allocation. |
| Compaction cannot solve it directly. | Compaction can reduce it. |


4.4 Segmentation Memory Management

4.4.1 Basic Concept
Definition: Segmentation is a memory management technique in which a program is divided into variable-sized logical segments.

Examples of Segments:
1. Code Segment.
2. Data Segment.
3. Stack Segment.
4. Heap Segment.
Features:
1. Each segment has a different size.
2. Each segment represents a logical part of a program.
3. Logical address consists of segment number and offset.
4. Uses a segment table.
5. Supports memory protection and sharing.

Advantages:
- Supports logical division of programs.
- Easy sharing of segments.
- Provides protection.

Disadvantages:
- External fragmentation may occur.
- Segment table management is required.
- Memory allocation is complex.

4.4.2 Segmentation Hardware
Segmentation uses a segment table.

Each segment table entry contains:
1. Base – Starting physical address of the segment.
2. Limit – Length of the segment.
Logical Address:
< Segment Number, Offset >

Address Translation:
1. CPU generates segment number and offset.
2. Segment number is used to access the segment table.
3. Offset is checked against the segment limit.
4. If valid, offset is added to the base address.
5. Physical address is generated.
Formula:

Physical Address = Segment Base + Offset

If offset is greater than or equal to the segment limit, an error trap occurs.

4.5 Paging Memory Management

4.5.1 Basic Concept
Definition: Paging is a memory management technique in which logical memory is divided into fixed-size blocks called pages and physical memory is divided into fixed-size blocks called frames.

Features:
1. Pages are of equal size.
2. Frames are of equal size.
3. Any page can be stored in any available frame.
4. Uses a page table for address translation.
5. Eliminates external fragmentation.

Advantages:
- No external fragmentation.
- Efficient memory utilization.
- Supports virtual memory.
- Easy memory allocation.

Disadvantages:
- Internal fragmentation may occur.
- Page table requires extra memory.
- Address translation creates overhead.


4.5.2 Hardware Support
Paging hardware uses a page table to translate logical addresses into physical addresses.

Logical Address contains:
1. Page Number (p).
2. Page Offset (d).
Physical Address contains:
1. Frame Number (f).
2. Frame Offset (d).
Address Translation:
1. CPU generates a logical address.
2. Page number is used to access the page table.
3. Page table provides the frame number.
4. Offset remains unchanged.
5. Frame number and offset form the physical address.

Important Components:
- Page Table – Maps pages to frames.
- PTBR – Page Table Base Register stores the starting address of the page table.
- TLB – Translation Lookaside Buffer stores recently used page table entries for faster translation.


4.5.3 Protection
1. Each page table entry contains protection information.
2. Read, write and execute permissions are provided.
3. Valid-invalid bit indicates whether a page is valid.
4. Prevents unauthorized memory access.
5. Protects processes from accessing other processes' memory.
4.5.4 Shared Pages
1. Allows multiple processes to share the same memory pages.
2. Common code can be shared between processes.
3. Saves physical memory.
4. Shared code is usually read-only.
5. Data pages can also be shared when required.
Example: Multiple users running the same program can share its common code pages.


4.6 Demand Paging
4.6.1 Basic Concept
Definition: Demand paging is a virtual memory technique in which a page is loaded into main memory only when it is required.

Working:
1. Process starts execution.
2. Required page is checked in memory.
3. If page is present, execution continues.
4. If page is absent, page fault occurs.
5. OS finds the required page on secondary storage.
6. Loads the page into an available frame.
7. Updates the page table.
8. Restarts the interrupted instruction.

Advantages:
- Saves memory.
- Reduces initial loading time.
- Allows execution of large programs.
- Increases degree of multiprogramming.

Disadvantages:
- Page faults cause delays.
- Requires additional hardware and OS support.
- Excessive page faults reduce performance.


4.6.2 Performance of Demand Paging
Effective Access Time (EAT):

EAT depends on memory access time and page fault rate.

Formula:

EAT = (1 − p) × ma + p × page fault service time

Where:
- p = Page fault rate.
- ma = Memory access time.
- Page fault service time = Time required to handle a page fault.
Important: Page fault service time is much higher than normal memory access time because disk operations are involved.
4.7 Page Replacement Algorithms
Definition: Page replacement algorithms decide which page should be removed from memory when a new page needs to be loaded and no free frame is available.


4.7.1 FIFO (First In First Out)
Definition: FIFO replaces the page that entered memory first.

Working:
1. Pages are loaded into frames.
2. Oldest page is replaced first.
3. New page is inserted.
4. Replacement follows arrival order.
Advantages:
- Simple to implement.
- Easy to understand.
Disadvantages:
- May replace frequently used pages.
- Can suffer from Belady's Anomaly.
Belady's Anomaly: Sometimes increasing the number of page frames increases the number of page faults.


4.7.2 Optimal Page Replacement
Definition: Optimal page replacement replaces the page that will not be used for the longest time in the future.

Working:
1. Check the future page references.
2. Find the page whose next use is farthest away.
3. Replace that page.
4. Continue the process.

Advantages:
- Gives minimum possible page faults.
- Used as a standard for comparison.

Disadvantages:
- Future page references are not known.
- Not practically implementable in general operating systems.


4.7.3 LRU (Least Recently Used)
Definition: LRU replaces the page that has not been used for the longest time in the past.

Working:
1. Track the recent usage of pages.
2. Identify the least recently used page.
3. Replace it with the new page.
4. Update the page usage information.

Advantages:
- Uses past behaviour to predict future use.
- Generally performs better than FIFO.

Disadvantages:
- Requires tracking page usage.
- Implementation can be costly.
MFU (Most Frequently Used)
Definition: MFU replaces the page that has been used the maximum number of times.

Working:
1. Maintain a counter for each page.
2. Count how frequently each page is used.
3. Select the page with the highest count.
4. Replace it with the new page.

Advantages:
- Can be useful in certain page usage patterns.
- Uses frequency information.

Disadvantages:
- Frequently used pages may be important.
- Performance depends on page reference patterns.


4.7.4 Second Chance Algorithm
Definition: Second Chance is an improved FIFO page replacement algorithm that uses a reference bit to give recently used pages another chance.

Working:
1. Each page has a reference bit.
2. When a page is accessed, its reference bit becomes 1.
3. Oldest page is checked for replacement.
4. If reference bit is 0, page is replaced.
5. If reference bit is 1, it is reset to 0 and the page gets another chance.
6. The next page is checked.

Advantages:
- Better than simple FIFO in many situations.
- Considers recent page usage.
- Reduces unnecessary replacements.

Disadvantages:
- More complex than FIFO.
- May require scanning multiple pages.


Important Comparison of Page Replacement Algorithms

| Algorithm | Replacement Basis |
|---|---|
| FIFO | Oldest loaded page |
| Optimal | Page used farthest in future |
| LRU | Least recently used page |
| MFU | Most frequently used page |
| Second Chance | FIFO with reference bit |




UNIT 5: System Security

5.1 The Security Problem
Definition: System security refers to protecting computer systems, data and resources from unauthorized access, misuse, modification and destruction.

Main Security Goals:
1. Confidentiality – Information should be accessible only to authorized users.
2. Integrity – Data should not be modified by unauthorized users.
3. Availability – Resources should be available when required.
4. Authentication – Verifies the identity of users.
5. Authorization – Determines what an authenticated user can access.


Common Security Problems:
- Unauthorized access.
- Data theft.
- Malware attacks.
- Data modification.
- Network attacks.
- Password attacks.


5.2 Program Threats
Program threats are malicious programs or techniques that damage systems or steal information.

5.2.1 Trojan Horse
Definition: A Trojan Horse is a malicious program that appears to be useful or legitimate but performs harmful activities secretly.

Features:
1. Disguises itself as genuine software.
2. Can steal confidential information.
3. May damage files.
4. Can create unauthorized access.
5. Requires users to execute or install it.
Example: A fake software application that steals passwords.


5.2.2 Trap Door
Definition: A Trap Door is a hidden entry point in a program that allows unauthorized access by bypassing normal security checks.

Features:
1. Bypasses normal authentication.
2. Provides secret access to a system.
3. Can be intentionally inserted by a programmer.
4. Creates security risks.
Example: A hidden password that allows access to a program.


5.2.3 Logic Bomb
Definition: A Logic Bomb is malicious code that executes when a specific condition or event occurs.

Features:
1. Remains inactive until triggered.
2. Executes when a particular condition is satisfied.
3. Can delete or modify files.
4. May cause system damage.
Example: A program that deletes files on a specific date.


5.2.4 Stack and Buffer Overflow
Stack Overflow:
1. Occurs when the call stack exceeds its allocated memory.
2. Usually happens due to excessive recursion or large stack allocation.
3. May crash the program.
4. Can sometimes be exploited to execute malicious code.


Buffer Overflow:

Definition: Buffer Overflow occurs when a program writes more data into a buffer than its allocated capacity.

Features:
1. Extra data overwrites adjacent memory.
2. Can cause program crashes.
3. May allow attackers to execute malicious code.
4. Occurs due to improper input validation.
Example: Storing 20 characters in a buffer that can hold only 10 characters.


5.2.5 Viruses
Definition: A computer virus is a malicious program that attaches itself to other files or programs and replicates when the infected program executes.

Features:
1. Attaches itself to files or programs.
2. Replicates itself.
3. Can corrupt or delete data.
4. Can slow down the system.
5. Usually requires a host program to spread.

Types of Viruses:
1. Boot Sector Virus – Infects the boot sector.
2. File Virus – Infects executable files.
3. Macro Virus – Infects documents containing macros.
4. Polymorphic Virus – Changes its code to avoid detection.
5.3 System and Network Threats


5.3.1 Worms
Definition: A Worm is a standalone malicious program that replicates itself and spreads across computer networks.

Features:
1. Does not require a host file.
2. Spreads automatically through networks.
3. Consumes network bandwidth.
4. Can slow down systems.
5. May install other malware.


Difference between Virus and Worm:


| Virus | Worm |
|---|---|
| Requires a host file or program. | Standalone program. |
| Usually spreads when infected files execute. | Spreads automatically through networks. |
| Infects files. | Exploits network vulnerabilities. |
| Replication depends on host execution. | Can replicate independently. |

5.3.2 Port Scanning
Definition: Port scanning is a technique used to identify open ports and available network services on a computer.

Features:
1. Checks different network ports.
2. Identifies active services.
3. Helps detect security vulnerabilities.
4. Used by network administrators.
5. Can also be used by attackers to find weaknesses.
Example: Checking whether ports 80 and 443 are open on a web server.


5.3.3 Denial of Service (DoS)
Definition: Denial of Service is an attack in which an attacker makes a computer system or network service unavailable to legitimate users.

Features:
1. Sends excessive requests to a server.
2. Consumes system resources.
3. Makes services slow or unavailable.
4. Interrupts normal operations.

Types:
1. DoS – Attack originates from a single source.
2. DDoS – Distributed Denial of Service uses multiple systems to attack a target.


5.4 Cryptography as a Security Tool
Definition: Cryptography is the technique of securing information by converting readable data into an unreadable format.

Important Terms:
1. Plaintext – Original readable message.
2. Ciphertext – Encrypted unreadable message.
3. Encryption – Converting plaintext into ciphertext.
4. Decryption – Converting ciphertext into plaintext.
5. Key – Value used for encryption and decryption.


5.4.1 Encryption
Definition: Encryption is the process of converting readable data into an unreadable format using an encryption algorithm and key.

Types of Encryption:

1. Symmetric Encryption
1. Uses the same key for encryption and decryption.
2. Fast and efficient.
3. Key must be shared securely.
4. Example: AES.
2. Asymmetric Encryption
1. Uses two different keys.
2. Public key is used for encryption.
3. Private key is used for decryption.
4. Provides secure key exchange.
5. Example: RSA.


Difference:
| Symmetric Encryption | Asymmetric Encryption |
|---|---|
| Uses one key. | Uses two keys. |
| Faster. | Generally slower. |
| Key sharing is difficult. | Public key can be shared openly. |
| Example: AES. | Example: RSA. |

5.5 User Authentication
Definition: User authentication is the process of verifying the identity of a user before allowing access to a computer system.

Types of Authentication:
1. Password-Based Authentication – Uses username and password.
2. Biometric Authentication – Uses fingerprint, face or iris.
3. Token-Based Authentication – Uses security tokens or smart cards.
4. Two-Factor Authentication (2FA) – Uses two different authentication factors.

Authentication Factors:
1. Something You Know – Password or PIN.
2. Something You Have – Smart card or mobile phone.
3. Something You Are – Fingerprint or face.

Advantages:
- Prevents unauthorized access.
- Protects confidential information.
- Improves system security.


5.6 Implementing Security Defenses
Security defenses are techniques used to protect computer systems against attacks.

Important Security Measures:
1. Authentication – Verify user identity.
2. Access Control – Restrict access to resources.
3. Encryption – Protect confidential information.
4. Antivirus – Detect and remove malware.
5. Firewall – Monitor network traffic.
6. Software Updates – Fix security vulnerabilities.
7. Backup – Restore lost or damaged data.
8. Intrusion Detection – Detect suspicious activities.
9. Strong Passwords – Prevent unauthorized access.


5.7 Firewalling to Protect Systems and Networks
Definition: A Firewall is a security system that monitors and controls incoming and outgoing network traffic based on predefined security rules.

Functions:
1. Blocks unauthorized network access.
2. Allows legitimate network traffic.
3. Monitors incoming and outgoing connections.
4. Protects internal networks.
5. Helps prevent network attacks.


Types of Firewalls:
1. Packet Filtering Firewall – Filters packets based on IP address, port and protocol.
2. Stateful Inspection Firewall – Tracks active network connections.
3. Proxy Firewall – Acts as an intermediary between users and external networks.
4. Application-Level Firewall – Filters traffic at the application layer.
5. Next-Generation Firewall (NGFW) – Provides advanced security features.

Advantages:
- Protects against unauthorized access.
- Monitors network traffic.
- Improves network security.
- Blocks suspicious connections.

Limitations:
- Cannot prevent every type of attack.
- Cannot fully protect against insider threats.
- Requires proper configuration.


5.8 Computer Security Classification
Computer security classification refers to categorizing systems according to their security requirements and level of protection.

The Trusted Computer System Evaluation Criteria (TCSEC) classifies computer systems into four major divisions.
1. Division D – Minimal Protection
1. Provides the lowest level of security.
2. Does not meet higher security requirements.
3. Has minimal security controls.
4. Example: Systems that have failed higher-level evaluation.
2. Division C – Discretionary Protection
1. Provides user-based access control.
2. Includes authentication mechanisms.
3. Allows users to control access to resources.
4. Includes security auditing.
Subdivisions:
- C1 – Discretionary Security Protection.
- C2 – Controlled Access Protection.
3. Division B – Mandatory Protection
1. Provides mandatory access control.
2. Uses security labels.
3. Provides stronger security mechanisms.
4. Prevents unauthorized information access.
Subdivisions:
- B1 – Labeled Security Protection.
- B2 – Structured Protection.
- B3 – Security Domains.
4. Division A – Verified Protection
1. Provides the highest level of security in TCSEC.
2. Uses formal security verification.
3. Requires detailed security design.
4. Provides strong security assurance.
Remember the order:

D → C → B → A

Security level increases from D to A.
